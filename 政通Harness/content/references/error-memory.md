# 红线抑制清单（E1–E14）

本文件是**跨轮次错误内化机制**载体。

把每一条被指出的错误转化为**生成时的主动抑制信号**，
由各成员在动笔 / 生成前强制加载，使同类错误不再复现。

## 使用协议（全员遵守）

1. **红线已内嵌**：各成员提示词的「红线」块已内嵌本库抑制信号，
   **常规流程不读本库**；
   本库仅在争议深查、非常用文种、用户质询三种情形按需读 1 次，作为**权威事实源兜底**。
   生成前各成员依内嵌红线自发抑制，**无需外部重复提醒**。

2. **主动抑制**
   生成过程中一旦命中某条「抑制触发」，**立即自发切换为「正确形式」，无需外部指令重复**
   ——这是内化，不是提醒。

3. **标红兜底**
   若仍不慎复现，由 **G9「历史错误零复现」** 门禁拦截，
   并标注「历史错误复现·已抑制」后退回责任成员订正。

4. **持续沉淀**
   每指出一类新错误，由主理人追加一条模式并更新「来源」，
   同步刷新各成员提示词顶部的红线引用块。

## E1 日期格式错误

- **错误模式**：成文日期或落款使用「×月×日」占位，或使用汉字数字。
- **错误表现**：`二〇二六年八月二日`；`×月×日`。
- **正确形式**：按 GB/T 9704，成文日期一律用阿拉伯数字 `2026 年 8 月 2 日`；
  附件说明、发文字号等要素按格式情景化规则同步激活。
- **抑制触发**：任何含「月 / 日」的落款或日期表述，
  若为汉字数字或占位符，**立即转写为阿拉伯数字规范格式**。
- **判定与退回责任方**：骆准绳（G1 版式域，**唯一**）。

## E2 逻辑自相矛盾

- **错误模式**：同一文书中「现状已无问题」与「仍提出诉求 / 申请支持」并列，
  构成自我矛盾（典型：账面平衡却申请补助）。
- **错误表现**：`本镇账面平衡、无资金缺口` 紧接 `特申请专项补助 50 万元`。
- **正确形式**：先陈述「申请前状态 / 困境 / 缺口」
  （如「受运维成本上涨影响，本级财力难以全额保障，运维经费存在缺口 X 万元」），再导出诉求；
  现状与诉求形成「**困境 → 诉求**」因果闭环，无自我否定。
- **抑制触发**：凡出现「平衡 / 无缺口 / 已解决」类表述又伴随「申请 / 请求 / 争取」类诉求，
  立即重构为「困境 → 诉求」因果链，并比对《因果备忘录》核心目的。
- **判定与退回责任方**：陈纲举（结构域）。

## E3 报告请示混淆

- **错误模式**：报告夹带请示事项，或文种错配；
  违反「报告不夹请示、请示一文一事、事前行文」。
- **错误表现**：报告中出现「妥否，请批示」「拟申请……请批复」等请示性结语或诉求；
  或以报告行文向上级提出批准请求。
- **正确形式**
  - **报告**＝汇报既往（现状 → 做法 → 成效 → 问题 → 打算），**不夹带请示事项**；
  - **请示**＝事前行文、一文一事、专述「理由 → 事项 → 结语」；
  - 文种选择依《条例》第八条，由文择体把关。
- **抑制触发**：生成报告类文稿时若出现请示性诉求 / 结语，
  **立即剥离并建议改走请示文种**；生成请示时核对一文一事与事前行文。
- **判定与退回责任方**：文择体。

## E4 归因浅层化

- **错误模式**：归因止步于「资源不足」「机制不健全」「意识不强」「重视不够」
  等表层 / 中层表述，未下探至治理逻辑层。
- **错误表现**：`群众参与不足，主要是群众意识不强`；`政策落地难，在于基层执行不力`。
- **正确形式**：归因须达治理逻辑层——
  如「群众参与不足」应归因为「治理模式以行政主导为主、群众自治平台
  （议事会 / 监督委员会 / 线上参与渠道）缺失，参与缺乏制度化通道与反馈闭环」；
  「政策落地难」应归因为「政策供给与基层实际适配不足、
  权责与资源不匹配（权随事走 / 人随事走 / 钱随事走未落实）、考核激励导向偏差」。
- **抑制触发**：凡成因仅述「资源 / 机制 / 意识」表层且无治理逻辑层归因者，
  **立即强制下探重构**；
  陈纲举须在《因果备忘录》标注「归因深度声明」（达至哪一层、为何为根因）。
- **判定与退回责任方**：陈纲举。

## E5 附注 / 版记格式缺漏

- **错误模式**：成文日期已规范但附注（如联系人 / 联系电话，依 GB/T 9704 7.3.6）缺失或格式不准；
  版记（分隔线、抄送机关、印发机关和印发日期）缺失或编排不规范；
  页码缺位或编排不规范（**页码属版式要素，不在版记之内**）。
- **错误表现**
  - 上行文（请示 / 报告）无「联系人及联系电话」附注
  - 版记漏「印发机关 / 印发日期」
  - 页码未用阿拉伯数字或未距版心下边缘 7 mm
- **正确形式**：依文种 / 方向**无条件**补全附注与版记全部要素——
  - 上行文须标「联系人、联系电话」（附注，居左空二字加圆括号编排于成文日期下一行）
  - 版记含抄送机关、印发机关和印发日期，
    分隔线与页码（阿拉伯数字，一字线上距版心下边缘 7 mm）规范呈现
- **抑制触发**：产出格式壳时**无条件**跑一遍「格式完整性自检清单」
  （版头 → 主体 → 版记 → 附注 → 排版），
  **不因任务简单 / 提示词未提格式而省略任一要素**。
- **判定与退回责任方**：骆准绳。

## E6 归因表述越界（政治表述闸口）

- **错误模式**：治理逻辑层归因（E4 强制下探的产物）在**上行文**中被直陈，
  构成对上级政策、考核导向、制度设计的直接批评。

  > E4 要求「下探到治理逻辑层」，E6 约束「下探成果如何随行文方向表述」，
  > **二者串行不冲突**。

- **错误表现**
  - 向上级报送的请示 / 报告中写 `政策供给与基层实际适配不足`
  - `考核激励导向偏差，致基层疲于应付`
  - `上级制度设计缺乏上位依据`
- **正确形式**：**归因内核保留、批评指向消解**，按行文方向转换表述
  - **上行文**改建设性建议式：
    「建议进一步完善××领域制度供给，增强政策与基层实际的适配性」；
    「恳请在考核指标设置上统筹条线要求，减轻基层多头报送负担」
  - **下行文 / 内部报告 / 平行商洽**可据实直陈，
    但仍须留有余地，**不点名批评具体上级机关**
- **抑制触发**：凡归因表述含「政策供给不足 / 考核激励导向偏差 / 制度供给缺位 /
  权责配置失衡 / 缺乏上位依据」等指向上级的判断，先核 D-Card 的行文方向；
  方向为上行即**立即转换为建议式表述**，并在回传中标注「E6 已适配·上行文」。
- **判定与退回责任方**：骆准绳（属 G2 合规域政治表述子项，
  **硬门禁不得降为 warning**）；
  **执行方由主理人分派**——涉归因层级 → 陈纲举，仅涉措辞转换 → 辞达意。

## E7 数据状态混域

- **错误模式**：同一「对象·属性」的数据跨声明域重复陈述
  （如「已救出 7 人」与「仍被困 5 人伤亡核实中」同列「已确认」）；
  或动态截止值无时间戳；或对象整体打包判态掩盖属性级差异。
- **错误表现**
  - D-Card 把「已救出 7 人（含伤情）」与「仍被困 5 人（伤亡核实中）」同列「已确认」
  - 成稿在「已核实情况」与「待核实情况」两域重复陈述同一对象实体数据
- **正确形式**：**先标注后转写**
  - 段落生成前对本段全部数据对象按「对象·属性」登记《数据状态台账》
    （可靠度态 R3 × 时效态：定值 / 截至值 / 待核），再自然语言转写
  - 同一「对象·属性」全文**仅归一处声明域**，
    跨域只引指引句（「××情况见第三部分」），**禁止第二域重复陈述实体数据**
  - 时效态为「截至值」须显式携「截至××时」
- **抑制触发**：凡段内出现「仍在核实 / 尚无 / 正在统计」字样
  而该段处于「已核实」声明域，**立即拆分归域**；
  凡动态数无时间戳，**立即补「截至××时」或改「定值」标注**。
- **判定与退回责任方**：骆准绳（属 G2 事实与合规域，数据状态台账为 G2 唯一取证字段）；
  域归属争议归陈纲举（结构责任方），时间戳与措辞归辞达意。

## E8 主体排序错位

- **错误模式**：多主体并列枚举未按职权归口、牵头主责、政治位阶、党内序列排序
  （如「消防、应急、卫健、住建」按词频排列），
  或领导同志名次序列按语感推断，或「等」字掩盖排序依据缺失。
- **错误表现**
  - 成稿「消防、应急、卫健、住建」并列
  - 领导同志排名按熟悉度排列
  - ≥3 主体枚举无排序依据随附
- **正确形式**：**先定场景再定序列**
  - 应急牵头 → 主战 → 行业主管 → 属地 → 保障
  - 抄送：党委 → 人大 → 政府 → 政协
  - 党委机关列政府机关之前；党组在前
  - 凡 ≥3 并列主体必随附 **1 行排序依据**
  - 领导名次序列不确定一律**升提问硬停车，禁止推断**
- **抑制触发**：凡正文枚举 ≥3 个并列行政主体而未附《主体排序表》（顺序 + 依据），
  **立即停写**并触发文择体强制编入产表；
  凡领导同志名次序列不确定，**立即升提问，不按语感排序**。
- **判定与退回责任方**
  - 文择体：排序权威源，产出《主体排序表》回填 D6
  - 骆准绳：G2「主体排序合规」子项终审（E8 落在 G2 合规域，与 E7 同构），命中即硬退回
  - 辞达意：落写执行责任方
  - 规则库见 `references/admin-ordering-rules.md`

## E9 模态语态混用

- **错误模式**：跨模态句式混用
  - 陈述态文种（报告）植入条件假设句（「一旦……即……」）或请求句
  - 请求态文种（请示）无明确请求句
  - 指令态文种（通知）只描述不指令、缺祈使引导语
  - 批复缺首句引文与明确态度
- **错误表现**
  - 报告「已落实情况」域内写「一旦发现二次失稳征兆即组织撤离」
  - 请示通篇陈述无「妥否请批示」
  - 通知无「现将……通知如下」引导语
- **正确形式**：先依《文种—方向—模态映射表》锁定模态，**全文锁定该模态语态**
  - 陈述态：禁条件假设句落「已实施」域；后续安排独立成段转确定性表述
  - 请求态：须一请一结
  - 指令态：须祈使引导语；批复首句引来文 + 明确态度
- **抑制触发**
  - 凡生成陈述态文种出现「一旦……即」「如……则」等条件假设句位于已落实措施域，
    **立即移至「下一步工作」段并转确定性表述**
  - 凡请求态文种无明确请求句，**立即补「妥否请批示」类结语**
  - 凡指令态无祈使引导语，**立即补「现将……通知如下」**
- **判定与退回责任方**：文择体（模态查表权威源）；
  文择体未编入时由主理人依 D-Card D1 研判并标 `[主理人研判]`（与 G3 例外同构）；
  执行责任方＝辞达意。

## E10 防御性拔高

- **错误模式**：模型被「政治安全」强化学习偏好绑架，
  凡需主观定级 / 定性 / 决策处，一律向「更稳妥、更重、更严」方向**无依据上调**——
  无伤亡、明火 15 分钟内扑灭的舆情事件主动给「中风险」；
  容错条款写成大段保护性声明；征求意见函刻意回避预设协调冲突。

  > 本质是「政治正确」被窄化为「不出错」，
  > 以层层加码的免责条款**置换果断判断与有效执行**。

- **错误表现**
  - `本起舆情事件（无伤亡、明火 15 分钟内扑灭）经综合研判，风险等级为中风险`
  - `（容错条款）如遇任何争议，由本单位承担一切协调责任，确保不因追责影响工作推进`
  - `（征求意见函）请贵局研提意见（未预设若意见相左的裁决路径）`
- **正确形式**：定级 / 定性 / 容错须走「**事实 → 推演 → 结论**」三步链，
  结论可回溯至依据链；无事实支撑不得上调，
  亦不得为回避冲突而模糊预设
  （模糊预设须显式标注待协调分歧点，由闭环推演节点②补全裁决路径）；
  容错 / 免责条款须具体、克制、指向明确情形，**不得写成大段保护性声明**。

  > **对称纪律**：禁止无依据压低
  > （避免从「防御性拔高」滑向「防御性压低」）。

- **抑制触发**
  - 凡风险等级 / 定性结论 / 容错幅度缺乏事实推演支撑，**即自发压下**，
    改走三步链并标注依据
  - 凡容错条款呈「大段免责」形态，**即拆为具体情形**
- **判定与退回责任方**：骆准绳（属 G2 定性域，**硬门禁不得降为 warning**）；
  主理人终核。
  配套见 `references/compliance-rules.md`「定级纪律与负面定级清单」。

## E11 正文层污染

- **错误模式**：把「请用户核实」「主理人研判」「假设待核」等审核元信息
  **伪装成正式行文叙述句**混入正文，
  使正式稿与草稿界限模糊，增加后续甄别成本（「层混排」）。
- **错误表现**
  - `关于抽查比例，请用户核实具体数值后补充至正文。`（作为公文正文一段）
  - `本项工作由主理人研判按一般惯例处理。`（混在正式部署中）
- **正确形式**：审核元信息一律用**统一显式标注格式**留存于正文
  或聚合于文末《审核待办清单》——
  `［待核：……］` / `［未知·须向主管部门确认：……］` / `［主理人研判：……］` / `［假设·待确认：……］`；

  **正式陈述句中不得出现**「请用户」「待核」「主理人研判」等元指令词。

  标注为可识别格式，**可提取 / 批量剥离**（去掉标注即正式稿）。
- **抑制触发**：凡拟写「请用户……」「待核……」作为公文正式叙述句，
  **立即改为显式标注格式或移入文末清单**；
  由骆准绳 G1/G2 标注格式审查 + 主理人交付结构终核拦截。
- **判定与退回责任方**：骆准绳（属 G1/G2 域，标注格式审查）
  + 主理人（交付结构终核）。

## E12 元信息未索引

- **错误模式**：正文审核元信息未采用统一二维编号令牌，
  或文末《审核待办清单》与正文标注未建立一一映射——
  同一语义用不同符号表达（如「待核」与「未核验」混用）、标注与清单脱节。
- **错误表现**
  - `［待核：…］` 与 `（未核验）` 混用指同一待确认项
  - 正文某条标注在文末清单无对应行
- **正确形式**：采用二维编号令牌 `［A1·待补·用户：…］`
  （轴 A 性质·补/决/核/判 × 轴 B 责任人·用户/系统），每条挂唯一编号；
  文末清单升级为索引台账
  `编号 → 正文位置 → 待确认内容 → 建议动作`，与正文**严格配对**
  （规则见 `references/gate-manual.md` 的 R13）。
- **抑制触发**：凡正文出现审核元信息，**立即套用二维编号令牌并登记索引台账行**；
  缺编号或清单缺对应行即改格式 / 补行。
- **判定与退回责任方**：骆准绳（属 G1/G2 域，标注格式审查，与 E11 同构）
  + 主理人（交付结构终核）。

## E13 分歧未记录

- **错误模式**：纪要 / 征求意见函 / 协调函以「两局未能达成一致」一笔带过，
  未记录各方引用的法规依据与核心诉求，直接跳入议定事项，
  **削弱公文程序性证明功能**。
- **错误表现**
  - `经会议讨论，议定如下`（前无分歧记录）
  - `两部门存在分歧，现将有关要求明确如下`
- **正确形式**：正文须含「**分歧与协调**」段
  （逐方：主体 → 引用依据(条款) → 核心诉求 → 坚持/让步点），其后接议定事项，
  向审计 / 巡视证明充分博弈与正当程序
  （范式见 `references/doc-type-patterns.md` 纪要）。
- **抑制触发**：凡判为纪要 / 征求意见函 / 协调函，
  **立即在结构前置「分歧与协调」段**；缺即停写补结构。
- **判定与退回责任方**：陈纲举（结构责任方）+ 骆准绳（G5/G8 终核）。

## E14 例外接口缺失

- **错误模式**：对后续落地可能卡顿的环节
  （专家意见存档、预算追加审批、回访核验窗口等）**全部留白**，
  未预埋例外处理规则接口（「不可预见预案缺失」）。
- **错误表现**
  - 议定事项落款后无「若…则…」的后续动作 / 时限 / 审批路径
  - D9 例外接口清单为空，或仅列事项不列接口
- **正确形式**：每项实质义务须配「责任主体 + 触发条件 + 后续动作 / 时限 / 审批路径」
  - 专家意见 → 存档方式与责任方
  - 预算 → 追加审批程序与触发阈值
  - 回访 → 启动窗口与牵头方

  与 D9 台账**一一对应**。
- **抑制触发**：凡落一项实质决定，**立即在 D9 登记对应例外接口**；缺即补。
- **判定与退回责任方**：骆准绳（属 G2/G13 域）。
