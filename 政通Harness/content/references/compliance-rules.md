# 合规规则库（政策依据必引 + 法规适用三段论）

本文件是骆准绳合规线（G2）的**强制事实源**。

**政策引用是起步动作而非进阶动作**，
且引用必须附原文摘录（R9a）、禁止反向解释（R9b）、显式核验三态（R9c）。

## 一、强制触发范围（政策依据为必选项）

满足以下任一特征的公文 / 事项，**政策依据强制必引**（起步动作）：

| 类别 | 特征 |
|---|---|
| **公共事务决策** | 政策定调、工作部署、制度出台、标准制定 |
| **资金使用** | 预算安排、专项资金申请 / 分配 / 监管、补助 / 奖补 |
| **项目推进** | 项目建设、工程实施、招标采购、试点示范 |
| **资源调配** | 编制、资产、用地、指标等公共资源统筹与分配 |
| **考核问责** | 督查考核、追责问责、通报约谈、责任认定 |
| **改革试点** | 体制机制改革、自主创新、先行先试 |

**非强制（轻量依据即可）**：纯程序性告知（会议通知、常规值班安排）、
纯事务性流转（简单函件确认）等不涉及上述特征的公文，
允许仅以工作惯例 / 内部规程为轻量依据，不强制外接政策文件，**避免过度引用**。

## 二、起步检索模板（Phase 0.5 使用 · 由骆准绳执行）

事项进入起草流程、文种判定前，据陈纲举《因果备忘录》所列「诉求 / 因果节点」，
**自主判定**每个节点是否落入强制触发范围，对落入者主动检索并适配：

1. **事项定性**：本事项落入哪一强制触发类别（决策 / 资金 / 项目 / 资源 / 问责 / 改革）？
2. **政策域扫描**：该事项可能适用的上位政策、法规、规划、上级文件有哪些（**不限于用户提及**）？
3. **三段论判定**（见第三节）：大前提（条款范围）→ 小前提（本案事实）→ 结论（是否适用及适用环节）。
4. **一策一案映射**：判定适用的政策，须映射至本项目 / 本地区具体痛点或举措，**禁止仅贴文件名**。
5. **产出《政策依据适配表》**
   每条政策含「文件名称 + 适用结论（适用环节）+ 一策一案落地表述」
   + **原文摘录 ≤50 字 + 出处（文件名 + 条款号）（R9a）**，回填进《因果备忘录》。

## 三、三段论适用推理骨架（R9b 反向解释禁令前置）

### 大前提（条款内容与适用范围）

该法规 / 文件**管什么**？适用对象、事项、层级、地域、时限；核心概念与约束边界。

### 小前提（本案事实是否符合）

本案主体、事项、层级、时间**是否落入**大前提范围？
是否存在排除情形（超出范围、已被新法替代、与上位法冲突）？

### 结论（是否适用及适用环节）

是否适用、适用于哪个具体环节（论证依据 / 合规口径 / 免责依据 / 程序要求）；
引用方式与一策一案映射。

> **关键判定**
> - 三段论解决「**能不能引、引到哪**」
> - 一策一案解决「**引了怎么落地**」
> - 二者**串行**——先判适用，再映痛点
>
> **R9b 反向解释禁令**：不得从「未明示禁止」推出「允许」。
> 如某行为未被条款明示禁止，**只能得出「未禁止」，不得得出「允许 / 合规」**；
> 须向主管部门确认的情形一律标 `[未知·须向主管部门确认]`，**不得自行作合规背书**。

### 常见法规类型适用模板

| 法规类型 | 大前提 | 小前提 | 结论 |
|---|---|---|---|
| **党中央 / 国务院文件** | 宏观战略导向 | 本案是否属其覆盖领域与层级 | 适用于「立场与方向论证」环节，须映射至本单位具体业务，**不得仅贴文件名** |
| **部门规章 / 规范性文件** | 明确创设权利义务或程序要求，**注意生效时间与适用地域** | 本案是否落入调整范围 | 适用于「合规口径 / 程序要求」环节；超出范围明示「不适用」 |
| **地方性法规 / 上级通知** | 注意**层级效力**（下位法不得抵触上位法）与转发链 | 发文机关层级与本案主送 / 抄送关系是否匹配 | 适用于「执行依据」环节；转发类须按「转发机关＋被转发文件」组合规则核查 |

## 四、核验三态（R9c）

每条依据标注其一，**禁止「通行做法 / 通行范式」冒充结论**：

| 态 | 含义 |
|---|---|
| `[已核对原文]` | 已附原文摘录与出处，核对无误 |
| `[未核验]` | 「通行做法」等未经核实的说法，**不得作为合规结论支撑** |
| `[待向××确认]` | 须向主管部门 / 发文机关确认后方可定论 |

> **环境兜底**：无权威政策库 / 检索能力不可用时，
> **严禁虚构文号或臆测条款**，适用结论一律标 `[未知·须向主管部门确认]`
> 并列入交付异常清单。

## 五、与既有机制衔接

- 本库为 **G10「政策依据零缺失」** 与 **G2「事实与合规」** 的联合事实源。
- 陈纲举 Phase 0 因果备忘录**仅列**「诉求 / 因果节点」；
  骆准绳 Phase 0.5 据本库强制触发范围**自主判定**哪些节点需政策依据，
  并产出《政策依据适配表》。
- 主理人跨维度校验「政策依据 ↔ 诉求环节」为**强制命中**：
  政策须落到对应论证 / 合规环节，**不得悬空**。

## 六、正反案例

### 被动 → 主动 + 合规硬化

- **错误**：报告谈「推进基层治理数字化」却无任何政策依据，
  仅因提示词未要求引用而留白——属政策依据缺失（触发 G10）。
- **修正**：骆准绳 Phase 0.5 主动检索上位文件，给出适用结论（方向论证环节）
  + 一策一案映射（映射到本项目 / 地区的具体痛点举措）
  + 原文摘录与出处（R9a），回填备忘录，下游落写。

### R9b 违例

- **错误**：某事项未被条款明示禁止，便在文中写「法无禁止即可为 / 故可代签」——属反向解释。
- **修正**：须改为 `[未知·须向主管部门确认]`。

## 七、定级纪律与负面定级清单（M1 · E10）

**E10 防御性拔高**：凡需主观定级 / 定性 / 决策处，
一律无依据上调（无伤亡、明火 15 分钟内扑灭≠「中风险」）。

本节约束「定级 / 定性 / 容错」的漂移，与红线 **E10** 串行，
由骆准绳（G2 定性域）判定、主理人终核。

### 定级三步链（强制）

任何风险等级 / 定性结论 / 容错幅度，必须可回溯至：

| 步 | 内容 |
|---|---|
| **1. 事实** | 已确认的客观事实（无伤亡？明火时长？损失范围？） |
| **2. 推演** | 由事实到结论的因果推演（为何判此级、为何给此措辞） |
| **3. 结论** | 明确结论并标注依据链（「依据×事实 + ×推演，判定为×」） |

**缺任一步即不得下结论**；
不得用「综合研判」「经评估」等**空壳词**替代推演。

### 负面定级清单（禁止项）

| # | 禁止 | 说明 |
|---|---|---|
| 1 | **禁止无事实依据上调**风险 / 等级 / 定性 | 无伤亡 + 明火 15 分钟内扑灭 ≠「中风险」；不得以「若定低被追责」的**恐惧性反弹**替代事实推演 |
| 2 | **禁止层层加码免责条款** | 容错 / 免责条款须具体、克制、指向明确情形，**不得写成大段保护性声明**置换果断判断 |
| 3 | **禁止为回避冲突而模糊预设** | 征求意见函 / 协调函须预设若多部门意见相左的裁决路径，**不得刻意回避** |
| 4 | **禁止无依据压低**（对称纪律） | 避免从「防御性拔高」滑向「防御性压低」——上调 / 压低均须有事实推演支撑 |

> 本节的「禁止」只禁**无依据**的定向漂移，
> **不禁有依据的上调或压低**；
> 判定以「**三步链是否可回溯**」为准，**不以结论方向为准**。
