`编排器.跑到终(...)` 必须挂 `# pyright: ignore[reportAttributeAccessIssue]`（违反 D-018「类型错误不得用 ignore 掩盖」），

结果是**整条 TUI → 编排的接线没有类型保障**：传入任何对象都不报错，
而接线一断，界面**全静默**——没有任何异常、没有提示、没有日志。

`档位: object` 同理：档位值无类型约束，非法档位要到 `TIER_BY_ID[...]` 才 KeyError。

## #4 的误判是怎么来的

第一轮我写「投影层根本没有 `artifacts`」，依据是一条

```
grep -rn "artifacts" src/ --include=*.py | head -8
```

**`| head -8` 截断了输出**，只看到 `fakes.py` 与 `state_codec.py`，
没看到 `projection.py:133` 的

```python
artifacts: tuple[tuple[str, str], ...] = ()
```

于是我据此断言「`_最终正文()` 恒返回空串」，还把它列为最高危写进报告。

**实际**：`artifacts` 存在，并由 `ARTIFACT_READY` 在 `projection.py:162` 填充。
`getattr(投影, "artifacts", ())` **取得到值，函数正常工作**。
界面另有 569、641 两处**本来就是直接属性访问**，只有 651 那处用了 `getattr`。

这条误判的性质比原缺陷更值得记：**用被截断的输出当全量事实**，
且据此升级了风险级别（把「防御性写法」说成「现在就坏」）。

## #4 真正的缺口（仍然存在，只是不同）

`Projection` 协议**只声明 `accept` / `lines` 两个方法**，结构化字段一个都没声明，
而界面要读它们。后果：

1. 界面读 `.artifacts` 过不了类型检查，只能 `getattr` 兜底——
   兜底的名字写错会静默取默认值（本轮证伪实验证明：行为判据此时**不红**）；
2. `DebugProjection` 早期缺这 7 个字段，`--debug` 一跑就 `AttributeError`——
   当时的修法是改继承，**根因（协议不约束字段）没动**。

所以修复不是「补一个字段」，而是**给协议补齐 7 个字段声明**，
让「界面读投影字段」这条路重新受类型检查保护。

## 改类型后**立刻暴露**的两处真实缺口

这正是本轮最值得记的一点：**`object` 标注不掩盖运行时错误，它掩盖编译期检查**。

1. `结果.error.detail` —— `Result.error` 类型是 `AppError | None`，
   `is_error` 是普通 property 不做窄化，标真类型后立刻报
   「`detail` 不是 `None` 的属性」。此前被 `object` + `ignore` 盖住。
2. 两个替身缺成员（`_假编排` 的返回值没有 `error`、`_失败的编排` 没有 `事件`）——
   此前靠 `getattr` 兜底「通过」。**替身不完整被兜底遮住，
   和接线不完整被兜底遮住是同一个病**：两端都在缺东西，判据却全绿。

| `test_界面读投影字段不许用getattr兜底`（源码） | 🔴 红 |

**结论**：两类判据不可互相替代。行为判据只抓「已经坏了」，
抓不到「还没坏但埋了雷」——兜底写法在字段名正确时行为完全正常，
只有源码判据能拦住它。两者都要留。

## 判据自身的三次修正

写判据的过程里，判据自己错了三次，都由全量测试当场暴露：

1. 源码判据扫全文 → **把本仓文档字符串里写的「原先挂的是 `pyright: ignore`」
   当成了违规代码**，判据把自己判红。改用 `tokenize` 剔除 `COMMENT` 与 `STRING`。
2. 类型忽略本身就是注释，`tokenize` 会剔除它——故那条判据反过来做：
   用 `ast` 找出**文档字符串所在行**并排除，余下行的注释才算数。
3. 「实现字段不得多于协议」这条方向错了：`DebugProjection` 的
   `prefix`/`records` 是**正当的子类扩展**（只经 `lines()` 暴露，刻意不给界面读）。
   改为只对基类 `StandardProjection` 做双向严格检查。
