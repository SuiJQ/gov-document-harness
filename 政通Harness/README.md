# 政通

**政通人和** —— 一个只为一件事而生的公文写作专家团系统：**产出一篇高质量公文**。

## 它是什么

不是通用 Agent。它没有电脑操控权，没有命令行权限，不做"智能助手"，
也不试图什么都会。它是一条**为公文而设计的固定生产线**：

```
D-Lock（方向锁） → Phase 0（因果推演） → Phase 0.5（政策取证）
   → 起草 → 12 道取证门禁（G1–G13 去 G0/G6） → DG-X（交付一致终闸）
   → G12（用户原始诉求复核） → 成稿
```

> 门禁编号口径：G0–G13 共 14 项编号，其中 G0、G6 为自检，
> **正式门禁 12 道**。详见 `DECISIONS.md`。

## 设计原则

| 原则 | 含义 |
|---|---|
| **产出至上** | 任何设计取舍的唯一判据：能否让这篇公文更好 |
| **结构性安全** | 隔离靠文件系统权限，不靠提示词约束 |
| **软数据平级** | 提示词是一等工程资产：有版本、可 diff、可回滚、可评审 |
| **优化不简化** | 专家团的门禁与红线一条都不能砍 |
| **借机制不抄代码** | 提取成熟方案的机制层洞察，融合成自己的统一设计 |

## 目录结构

便携 zip 解压即用，**数据与程序同目录**（`DECISIONS.md` D-010）：

```
<程序目录>/
  content/            内容包 —— 公文知识与专家团提示词，随程序分发
  data/               AI 的产出 —— 唯一可写区
    <run-id>/
      shared/         公共交换区（成员间传递中间产物）
      workers/        每个成员一块草稿纸（用完即清，上限 3 个文件）
      output/         最终稿
  user/               用户给 AI 的文件 —— 只读
  system/             配置 / 日志 —— AI 完全不可见
```

`data/` `user/` `system/` 可被整体删除，程序启动时自动重建。
内容包独立于 `system/`，删 `system/` 不损失公文知识。

## 开发

```bash
uv venv .venv --python 3.11
uv pip install --python .venv/bin/python -e ".[dev]"
```

### 代码检查

```bash
cd Harness/政通Harness
../Supporter/check.sh          # 检查全部
../Supporter/check.sh --fix    # 顺便自动修（类型检查不参与自动修）

../Supporter/lint.sh           # Supporter 自己的自查（只开 F 类）
```

Ruff 管风格与静态缺陷，BasedPyright 管类型，**两者都跑，缺一不可**：
未用导入、未定义名只有 Ruff 查；类型问题只有 BasedPyright 查。
`src` 与 `tests` 一并纳入类型检查——测试是判据，判据自己不受检查不行。

**为什么入口在 `../Supporter/`**：开发期工具（检查器、网关、台账工具）
与主体分居两层（D-384），`Supporter/` 不进交付物。
`ruff check .` 与 `basedpyright` **都以项目根为界、不越出**，
故扫不到 Supporter——它靠 `lint.sh` 自查（**只开 F 类**：
会真出错的那几类，不刷行长、变量名这类风格项）。

### 跑测试

```bash
.venv/bin/python -m pytest tests/ -q
```

> 若提示 `No module named 'platformdirs.pytest_plugin'`，加环境变量
> `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` 绕开系统 venv 漏进来的插件。

第 1 步的三条判据均已机械验证：**零第三方依赖**、**全部 dataclass 均 `frozen` + `slots`**、
**全部值类型可 JSON 化**。

两个工具各管一段，**职责不重叠，缺一不可**：

| 工具 | 负责 | 独有职责 |
|---|---|---|
| **Ruff** | 格式与静态缺陷 | 未使用导入、未定义名（基于类型检查查不到） |
| **BasedPyright** | 类型检查 | 注解与实现不符、隐式 `Any`、缺属性注解 |

单独跑其中一个会漏问题：`ruff check` 通过不代表类型正确，
`basedpyright` 通过不代表没有死代码。选型依据见 `DECISIONS.md` D-083。
