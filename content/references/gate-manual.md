# 门禁详判手册（外置 · 按需读 1 次）

承接主理人提示词的 12 道门禁判据扩展、跨维度一致性校验与退回重做细则。

**G0 / G6 为自检项**（恒无客观证据，降级主理人自查，不占门禁序号），
正式门禁 **12 道**，逐个是：
**G1、G2、G3、G4、G5、G7、G8、G9、G10、G11、G12、G13**。

> **别把「12 道」当成连续编号区间数**：`G1–G13` 是 13 个格，
> 扣掉自检的 **G6** 才剩 12 道。写成区间会让人按连续 13 道理解——
> 第六轮检查实测本手册原文正是「G1–G13 共 12 道」，
> 数字对、记法歧义，故改为**直接列出编号**。

主理人首次过 Gate 前读 1 次即可，**无需每轮重读**。

> ### 执行顺序（**以本框为准，不看小节排列**）
>
> 本手册的小节按 **Gate 编号**排列便于查阅；
> 但**终局三道有先后依赖**，实际执行顺序是：
>
> ```
> G1 … G10（可并行复核）
>    ↓
> G11 硬约束零沉降 ──┐
> G13 折中论证透明 ──┤
>    ↓              │
> 交付一致性闸 DG-X ──┤  ← 核「交的是不是 D-Card 要的那一份」
>    ↓              │
> G12 用户输入回看 ──┘  ← 核「D-Card 是否真为用户要的那一份」，最终闸
> ```
>
> **G12 必须最后执行**：它以「DG-X 已过」为前提，
> 兜住 D-Card 本身把用户原意带偏的情况。
> **跳过 DG-X 直接做 G12，或先做 G12 再做 DG-X，均属流程错误。**

## 降级自查项（不占门禁序号）

- **G0 质量恒定**：主理人自查「未因简繁降标」，保留仅防「全绿假象」。
- **G6 受众可追溯**：成稿语气 / 详略 / 重点可回溯至受众画像；
  用户未提供受众时，主理人基于文种 / 方向推断合理受众并标注假设。

## G1 格式零缺项（骆准绳）

### 取证式 18 项版式勾选表（G1 唯一口径）

**版头（5）**

| # | 要素 |
|---|---|
| ① | 份号 |
| ② | 密级和保密期限 |
| ③ | 紧急程度 |
| ④ | 发文机关标志 |
| ⑤ | 发文字号（居中） |

**主体（9）**

| # | 要素 |
|---|---|
| ⑥ | 标题三要素（发文机关 + 事由 + 文种） |
| ⑦ | 主送机关 |
| ⑧ | 正文 |
| ⑨ | 附件说明 |
| ⑩ | 发文机关署名 |
| ⑪ | 成文日期（阿拉伯数字右空四字） |
| ⑫ | 印章（端正下压署名日期） |
| ⑬ | 附注（上行文联系人电话 7.3.6） |
| ⑭ | 附件 |

**版记（3）**

| # | 要素 |
|---|---|
| ⑮ | 分隔线（首末粗线，中间细线） |
| ⑯ | 抄送机关 |
| ⑰ | 印发机关和印发日期（7.4.2） |

**版式（1）**

| # | 要素 |
|---|---|
| ⑱ | 页码（阿拉伯数字，距版心下 7mm；**版式要素，不属版记**） |

> **口径警示**：GB/T 9704—2012 的**版记只含分隔线、抄送机关、印发机关和印发日期**
> （详见 `references/gbt9704-format.md` 第三部分），**页码不在版记之内**，
> 而是独立编排于版心下边缘之下（该文件「四、页码编排」）。
> 故 18 项按 **版头 5 + 主体 9 + 版记 3 + 版式 1** 分组，**总数 18 不变**。

> - **上行文附加**（不入 18 固定项，随文种激活）：签发人（右空一字）。
> - **排版规范**（独立，不入勾选表）：A4；版心 156mm×225mm；
>   正文一般用 3 号仿宋体字；**每面 22 行、每行 28 字**。
>
> **口径警示**：常见排版软件以「固定行距 28～29 磅」实现该行数，属**换算实现值**。
> 引用国标时**不得写作「国标规定行距 28 磅」**。

### 复杂度无关铁律

无论任务简繁、提示词长短、领域切换，**18 项无条件完整呈现**
（含附注 / 版记 / 签发人），命中 E5 即补。

### 格式情景化激活

依文种 / 方向自动激活对应规则，**不得机械套用致遗漏**。

## G2 事实与合规（骆准绳）

- 政策一致、无未核事实、无越权承诺、无涉密误判。
- **引用须三段论适用**（大前提 → 小前提 → 结论 + 适用环节）
  + **一策一案内化**（映射到本项目 / 地区痛点举措），**禁仅贴文件名**。

### 依据硬化（R9）

| 条 | 要求 |
|---|---|
| **R9a 法条原文强制** | 引用任何条款必须附**原文摘录 ≤50 字 + 出处（文件名 + 条款号）**；无原文者**不得作为依据，仅作线索** |
| **R9b 反向解释禁令** | **不得从「未明示禁止」推出「允许」**；此类结论一律标 `[未知·须向主管部门确认]`，列入交付异常清单残留风险项 |
| **R9c 核验三态** | `[已核对原文]` / `[未核验]` / `[待向××确认]`；「通行做法 / 通行范式」**强制归 `[未核验]`**，不得作为合规结论支撑 |

### 政治表述子项（E6 · 硬门禁）

治理逻辑层归因写入上行文时须转为建设性建议式表述，
不得直批上级政策 / 考核导向 / 制度设计（判定责任方＝骆准绳）。

> **本项不得降级为 warning**——
> 历史缺陷即在于此处只做人工提示而无门禁，构成全包最大风险敞口。

### 数据状态双轴（R11·E7）

G2 取证须附《数据状态台账》——每行登记
「对象·属性 / 可靠度态(R3) / 时效态(定值·截至值·待核) / 时间戳 / 声明域归属」。

- 同一「对象·属性」**禁止跨声明域重复陈述实体数据**（跨域只引指引句）
- 时效态「截至值」须显式携时间戳
- 未附台账或混域即 **G2 硬退回**

### 主体排序合规（E8）

凡正文枚举 ≥3 个并列行政主体，G2 取证须含《主体排序表》（顺序 + 排序依据），
依据须可举证（牵头部 / 主战 / 行业主管 / 党内序列 / 党组在前等），
**无依据即硬退回**；领导名次序列不确定一律升提问硬停车。

规则库见 `references/admin-ordering-rules.md`。

### 与 G10 的关系

「政策依据齐备」子项与 G10 同源：**过 G10 即视为本子项通过，二者不重复退回。**

## G3 文种零错配（文择体）

文种 / 方向 / 级别与受众及事项完全匹配；受众画像由文择体一并产出。

### 模态锁定（E9）

文择体据 `references/doc-type-patterns.md`《文种—方向—模态映射表》机械判定模态，
填 D-Card D1（文种 + 方向 + 模态），**不增提问**。

模态一经锁定，全文语态锁定该模态，**禁跨模态句式混用**。

文择体未编入时，主理人依 D-Card D1 研判并标 `[主理人研判]`
（与 G3 现有例外同构）。

## G4 语言零歧义（辞达意）

无残留歧义、无口语空话、无 AI 生成痕迹、序号标点全规范；
敏感议题（资金 / 人事 / 问责）委婉留余地，
**禁财务术语生硬直陈与过度量化**。

### 语态一致（E9）

辞达意落写须对齐 G3 锁定模态：

| 模态 | 要求 |
|---|---|
| 陈述态 | 不落条件假设句于「已实施」域；后续安排转确定性表述 |
| 请求态 | 须有且仅一明确请求句 |
| 指令态 | 须有祈使引导语；批复首句引来文 + 明确态度 |

模态锁定后全文语态一致性为**生成即校验前置项**。

### 去 AI 味

按 `references/deai-rules.md` 执行，**无条件执行**，无外部依赖。

## G5 结构零断裂（陈纲举）

逻辑闭环、无缺失 / 冗余板块；
时序因果零矛盾——申请前 / 后状态不错置、
「理由 → 诉求」因果链完整、无自我矛盾 / 因果倒置。

### 分歧记录段（E13 · 程序性证明功能）

纪要 / 征求意见函 / 协调函正文须含「分歧与协调」段（或二级标题），
逐方列 `主体 → 引用依据(条款) → 核心诉求 → 坚持/让步点`，其后方接「议定事项」。

回避分歧、以「两局未能达成一致」一笔带过即触发 **E13 分歧未记录** 红线，
退回陈纲举补全结构 + 骆准绳核验。

> 该段向未来审计 / 巡视证明决策经充分博弈与正当程序，
> **非削弱权威**。与闭环推演节点②「分歧裁决路径」区分：
> 节点②为备忘录内推演，本段为正文须落的结构记录，**二者互补不替代**。

## G8 因果推演零缺项（陈纲举 · 含治理逻辑层归因）

凡申请 / 请求 / 建议 / 报告须有《因果备忘录》支撑；
归因达治理逻辑层（权责 / 治理模式 / 制度供给 / 平台缺失 / 激励相容），
**非资源 / 机制 / 意识表层**；
无备忘录或因果链断裂，退回陈纲举补全。
审核模式据原文反推因果链完整性。

### 三层归因框架

| 层级 | 典型表述（**止步于此 = 未达标**） | 特征 |
|---|---|---|
| **表层** | 资源不足、资金短缺、人员不够、意识不强、重视不够 | 把问题归于「量」或「态度」，未触及结构性成因 |
| **中层** | 权责错位、流程断点、激励缺失、信息不通、协调不力 | 触及运行环节，但未上升到制度 / 模式层面 |
| **治理逻辑层**（目标层） | 治理模式行政主导、群众自治平台缺失；制度供给不足、缺乏上位依据；激励不相容、权责配置失衡；条块分割、协同机制缺位 | 揭示资源配置背后的治理结构与制度成因 |

### 反例映射（表层 → 治理逻辑层）

| 表层（禁） | 治理逻辑层（须） |
|---|---|
| **群众参与不足**：群众意识不强 | 治理模式以行政主导为主，群众自治平台（议事会、监督委员会、线上参与渠道）缺失，参与缺乏制度化通道与反馈闭环 |
| **政策落地打折扣**：基层执行不力、宣传不到位 | 政策供给与基层实际适配不足，权责与资源不匹配（权随事走、人随事走、钱随事走未落实），考核激励导向偏差 |
| **跨部门协同难**：沟通不畅、配合不够 | 条块分割的治理结构下缺乏常态化协同机制与数据共享平台，权责边界模糊导致推诿 |
| **资金效益不高**：资金不足、使用效率低 | 投入机制碎片化、缺乏统筹整合，绩效问责与结果导向激励不相容 |
| **服务效能低**：人员少、设备旧 | 政务服务供给模式仍以部门本位为主，未转向以群众需求为导向的整体政府 / 平台化治理 |

### 使用协议

1. 完成归因时显式标注**「归因深度声明」**：达至哪一层 + 为何判定此为根因。
2. 凡归因止步表层 / 中层，须**强制下探**至治理逻辑层方可写入备忘录；
   下探受阻须标注「已穷尽下探·表层为实」，**不强行拔高**。
3. **E4 归因浅层化**：凡成因只述「资源不足 / 机制不健全 / 意识不强」
   而无治理逻辑层归因者，**强制下探**。

### 闭环推演五节点

G8《因果备忘录》须从「为什么写」延伸到「**发出去之后怎样**」，
五节点写入**同一份**备忘录：

| # | 节点 | 内容 |
|---|---|---|
| ① | **收文方反应预判** | 对方可能异议 / 推诿的具体点 |
| ② | **分歧裁决路径** | 若多部门意见相左，谁裁、依何裁（如「由牵头部门协调，依《××》第×条裁定」）；**征求意见函不得回避预设协调冲突**（呼应 E10 禁止模糊预设） |
| ③ | **遇阻后备动作** | 若协调失败 / 上级不支持，本级后备方案 |
| ④ | **折中论证（G13 框架）** | 凡涉两方妥协 / 量化项被压缩 / 被削减，须附完整论证链（四段式范式与兜底项拆解义务见 **G13 专章**） |
| ⑤ | **例外接口（D9）** | 对每项实质决定 / 义务，预置「责任主体 + 触发条件 + 后续动作 / 时限 / 审批路径」（红线见 **E14**） |

**缺任一节点即退回陈纲举补全。**

### 行文方向适配（E6 · 与 E4 串行的必经第二步）

**E4 解决「归因够不够深」，E6 解决「深归因怎么说才不越界」。**

| 行文方向 | 表述要求 | 示例转换 |
|---|---|---|
| **上行文**（请示 / 报告 / 意见上行） | 归因内核保留、批评指向消解，一律转**建设性建议式** | 「政策供给与基层实际适配不足」→「建议进一步完善××领域制度供给，增强政策与基层实际的适配性」；「考核激励导向偏差」→「恳请在考核指标设置上统筹条线要求」 |
| 下行文 / 内部报告 | 可据实直陈，但留有余地、不点名批评具体上级机关 | 保留原归因表述，措辞用「仍存在」「有待加强」 |
| 平行商洽（函 / 意见平行） | 中性陈述，不作价值评判 | 转述为客观情况说明 + 商洽诉求 |

- **执行分工**：陈纲举在「归因深度声明」后须追加一行**「表述适配标注」**；
  辞达意据此落写；骆准绳终审判定（E6 责任方），命中即硬退回。
- **禁止的规避方式**：不得为回避 E6 而放弃下探、退回表层归因——
  那将同时触发 E4。**二者是「先深挖、再得体」，不是二选一。**

## G10 政策依据零缺失（骆准绳）

强制触发范围（决策 / 资金 / 项目 / 资源 / 问责 / 改革）事项
须 ≥1 条「已判定适用 + 已一策一案内化」政策；
**缺失即退回骆准绳补全**。仅判「有无」，与 G2 不重复计分。

### 无政策库环境下的判定路径（防机制死循环）

**本包不内置政策全文库。**
骆准绳须按检索链逐级尝试并在回传中记录结果：

1. 用户提供的政策原文 / 附件
2. 环境可用的检索或知识库能力（具备则必须实际尝试并注明检索式）
3. 用户在 D-Card 或需求中指明的上级文件名 / 文号
4. `references/compliance-rules.md`（**只定「该不该引」，不产生依据**）

| 情形 | G10 判定 | 后续动作 |
|---|---|---|
| ①②③ 任一可得且已附原文摘录 | 通过 | 正常进入末端审查 |
| 四路径皆不可得，且已逐级记录尝试结果 | **不判「退回」，直接升级提问①** | 由用户补依据，或依下方「G10 受限豁免」书面担责；结论标 `[未知·须向主管部门确认]` 入异常清单 |
| 未记录检索链尝试结果即称「无库」 | **退回骆准绳** | 视为未尽检索义务，须补做并记录 |

> **反死循环铁律**：环境性缺失（无库 / 无网）
> **不得**按「同一闸退回 2 次 → 用户裁决」的常规路径空转，须一次性升级用户决策。
> 反复退回构成机制死循环，属严重设计缺陷。

### 用户确认豁免（优先链：用户明示授权 > 硬规则 > 默认规范）

- G1 / G2 / G3–G5 / G7–G9 因用户二次确认偏离：
  记「已知风险·已告知·用户确认」豁免并明示于定稿说明。
- **G10（政策合规底线）受限豁免**：**仅当用户明示且书面承担合规风险时方可豁免**，
  定稿说明强制标「政策依据缺失·用户确认担责」。

## 跨维度一致性校验（主理人独占 · 10 条）

| # | 校验对 | 内容 |
|---|---|---|
| 1 | 文种 ↔ 结构 | 报告不得夹带请示事项 |
| 2 | 受众 ↔ 诉求 | 受众期望行动 = 文档实际诉求 |
| 3 | 核心诉求权威源 | 陈纲举《因果备忘录》「核心诉求」为事项层权威源，文择体据此转化；**不一致以备忘录为准** |
| 4 | 受众详略 ↔ 结构重点 | 避免「扼要却冗长」错配 |
| 5 | 文种 / 方向 ↔ 语气 | 上行 / 下行 / 平行语气一致 |
| 6 | 受文层级 ↔ 越权表述 | 避免向不当层级行文却越权承诺 |
| 7 | 文种时态范式 ↔ 结构时序因果链 | 避免「已平衡却仍申请」式错置 |
| 8 | 法规适用结论 ↔ 诉求环节 | 引用须落到对应论证 / 合规环节 |
| 9 | **冲突裁决** | 见下方优先级 |
| 10 | **语域一致性** | 文种 / 方向（文择体）↔ 语域特征（辞达意）须与 **D8** 锁定一致；语域漂移（各机关语气趋同、读不出谁在说话）即判不一致，退回辞达意对齐 D8 |

### 第 9 条的裁决优先级

成员跨域结论冲突时，由主理人依第 1–8 条交叉校验并裁决，
**禁止成员互相直连覆盖结论**。

裁决基准（自高至低）：

```
D-Card
  > 陈纲举《因果备忘录》核心诉求（事项层）
    > 文择体受众 / 文种（前端研判）
      > 骆准绳合规结论
        > 辞达意语言表现
```

裁决结果记入交付说明。

## 退回重做机制与重试上限

- 任一 Gate 失败，**退回对应责任成员（非自行补改）**，
  附精确缺陷说明（Gate 编号 + 依据）；成员重出，主理人重过 Gate。

- **责任映射**
  G1 / G2 / G7 / G10 → 骆准绳；
  G3 → 文择体（未编入时主理人研判，标 `[主理人研判]`）；
  G4 → 辞达意；G5 / G8 → 陈纲举；G9 按红线归属退。

- **编制—门禁配平铁律**
  某档门禁含某 Gate，其责任成员必在该档编制内，**主理人不得代行取证**。
  唯一例外为 G3。
  据此 **Flash 档骆准绳必含**（G1 唯一取证方）。

- **重试上限**
  同一 Gate 退同一成员**至多 2 次**；第 2 次仍不过 → 走**提问③由用户裁决**，
  **主理人无权自行降标定稿**（堵死「标注残留风险定稿」出口）。

- **反向质询（零成本）**
  定稿前自问「若被上级退回，最可能因哪三点」，逐条回 Gate 复核，
  有实质问题即退。

- **档位范围**
  仅 **成文 Pro（全编制）** 做跨维度交叉复核；咨询 / Flash 免。
  咨询档不触发成品门禁，仅过交付一致性快速核。

## 交付一致性闸（DG-X · 主理人 · 须向用户举证）

终局闸，对照 D-Card 核「交的是不是他要的那一份」。

**反自证要求**：本闸责任方与取证方同为主理人，天然存在自审自证风险，
故取证不得停留于内部勾选，须产出**可复核对照表**并随交付输出摘要（≤5 行）：

| D-Card 条目 | 约定内容 | 成稿落点 | 符合 |
|---|---|---|---|
| D1 主件 | 文种 + 标题 + 份数 | 全文 / 标题行 | ✓ / ✗ |
| D2 配套件 | 逐项清单 | 附件×份 | ✓ / ✗ |
| D3 关键时点 | 定稿 / 报送截止 | 成文日期 / 正文×段 | ✓ / ✗ |
| D4 事实边界 | 禁止假设项 | 三态标注表 | ✓ / ✗ |
| D5 数据状态 | 台账逐行 | 成稿对应声明域落点 | ✓ / ✗ |
| D6 主体排序 | 排序表逐行 | 成稿对应枚举落点 | ✓ / ✗ |

- 任一项 ✗ 即判**交付失败**，**不得以「质量很好」抵消**，退回对应环节重做。

- D3 走过降级出口（用户拒绝确认）者，本表须标 `[待填·已告知]`，
  并在交付说明首行醒目提示，**不得静默勾 ✓**。

### 取证锚点纪律（R12 · 主理人执行）

本表「成稿落点」列**只填成稿内实际章节／段落**（如「一、已核实情况」「正文第三段」），
**禁填 D-Card 侧字段名**（如以「签发人」顶替「签批时点」）。

DG-X 前主理人须逐条回读成稿确认锚点存在，
**不可定位者判交付失败**。

> **纯机械复核只判字符串可定位性，不产出质量结论，
> 其输出不得作为本闸或任一 Gate 通过依据。**

## 标注索引规则（R13 · E12 与 E11 同构）

针对「元信息标注紊乱」——正文标注与文末清单未建立一一映射。

1. **正文**审核元信息一律采用二维编号令牌（轴 A 性质·补/决/核/判 × 轴 B 责任人·用户/系统），
   形如 `［A1·待补·用户：牵头部门全称］`，**每条挂唯一编号**。
2. **文末**《审核待办清单》升级为**索引台账**，
   逐行 `编号 → 正文位置 → 待确认内容 → 建议动作`，与正文标注**严格一一映射**。
3. **E12 元信息未索引**：正文标注无编号、或清单缺对应行、或编号与正文无法配对，
   即触发红线，退回骆准绳（G1/G2 标注格式域）订正。

该规则与 E11 单稿分区制同源，共同实现「草稿层指令注释」与「成品层正式文本」的清晰边界。

## G11 硬约束零沉降（骆准绳 · 机械核验）

针对注意力对长文本中部偏后量化指标 / 时限 / 金额的稀释（「语义沉降」）。

D-Card **D7 硬约束清单**须在动笔前登记全部量化硬指标
（比例 / 时限 / 金额 / 数量）及「落点章节」。

- **取证字段**：逐条约束的落稿核验结果（约束是否落入成稿）。
- **严格度**：任一 D7 约束未在成稿出现＝**硬退回**；
  但核验通过 **≠ 门禁通过**——主理人仍须逐条回读成稿，
  确认约束不仅「出现」且「落在正确语义位置」，**不得以「已跑过核验」抵消人工核验**。
- **失败处置**：任一约束失踪即退回责任成员（通常为辞达意 / 陈纲举）补全落点，
  **不得因「质量好」放行**。

> **机械核验的边界（防数值 / 单位假阳性）**：
> 核验仅验「约束文字是否落入成稿」（字符串可定位性），**不校验数值 / 单位正确性**——
> 成稿写「5‰」仍可能命中「5%」约束、举例段的「50 万」亦可能命中金额约束、
> 范围约束的「20–30℃」与「20℃ 至 30℃」等价。
> 故核验通过**绝不豁免**主理人终核对「数值 / 单位 / 语义是否真正正确」的判定。

## G12 用户输入回看（主理人 · 最终闸 · 置于 DG-X 之后）

DG-X 仅核「D-Card ↔ 成稿」，而 **D-Card 本身可能已把用户原意带偏**——此为本体系盲区。

G12 用**用户原始需求文本**作第三锚点，置于 DG-X 之后作为最终闸：

- **取证字段**：用户原始需求逐条 ↔ 成稿落点对照表
  （**源不同**：DG-X 源为 D-Card，G12 源为用户原话）。
- **严格度**：任一用户明确要求未满足（或 D-Card 偏离用户原意未纠偏）即**硬退回**，与 DG-X 同构。
- **与 DG-X 的关系**
  DG-X 先核「交的是否为 D-Card 要的那一份」，
  G12 终核「D-Card 是否真为用户要的那一份」；**二者串联，G12 为最后一道确认。**

## G13 折中论证透明（陈纲举框架 + 骆准绳终核）

针对「折中方案的行政逻辑不透明」——只做数字平衡、缺可行性论证。

凡属**两方妥协 / 量化项被压缩 / 被削减**的安排，
须在稿内或《折中说明》附**完整论证链**，**不得仅陈列结果数字**。

### 论证四段式

```
原值
  → 可削减科目枚举（逐项，如检测费、设计变更预留金、监理费、不可预见费等）
    → 每项削减额与理由
      → 压缩后值
```

**例**：「其他」项由 1600 万压至 980 万，须逐列被压缩的具体工作内容与对应金额，
并说明压缩是否经各方确认。

### 兜底项拆解义务

「其他」「不可预见」类兜底科目**不得整体含糊压缩**；
压缩比例超阈值（如 **≥30%**）须逐项论证，否则 G13 判未通过。

### 与 D9 / E14 协同

被削减项往往同步产生后续风险，须在 D9 预置对应例外接口
（如压缩后工期风险 → 触发预算追加审批程序的阈值与路径）；
**D9 缺项即触发 E14 例外接口缺失红线**。

### 取证字段

骆准绳终核须附「折中论证段落落点（章节 / 段首6字）」+「D9 台账配对行」；
主理人回读确认论证链完整、数值与理由可核验。

> 脚本可扩展识别 D7/D9 约束落稿，但**不得作为 G13 通过依据**，终核仍属骆准绳人工判定。

### 责任

框架由陈纲举在《因果备忘录》第④节点产出，
终核与退回责任方为骆准绳（属 G2/G13 域）；
纪要类另须满足 G5「分歧记录段」（E13）。
