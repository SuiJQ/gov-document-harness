# 法定文种模板骨架

> 本文件是**结构骨架**，不是范文成品。
> 落笔时须替换 `[方括号]` 中的占位，且**占位替换前禁止导出**（D-034）。
>
> **依据**：GB/T 9704—2012；`references/doc-type-patterns.md`（15 种法定文种范式）。

> ### 与去 AI 味的关系
> 模板是**防漏项**的，不是**照抄**的。
> 照搬模板句式正是 AI 味的来源之一
> （「为切实推进××工作，现将有关情况通报如下」类）。
> **填内容、不填套话**——句式可套，表述不可套。

## 一、请示

### 标准骨架

```
[发文机关] 关于 [请示事由] 的请示

[主送机关]：

[导语/依据]：
根据[法律、法规、政策依据]，[情况说明]。现将有关问题请示如下：

[主体/请示内容]：
一、[具体事项1]
    [详细说明：背景、现状、问题]

二、[具体事项2]
    [详细说明：请示的具体要求]

三、[必要附件说明]
    [相关文件、数据、材料等附件说明]

[结尾/请求语]：
妥否，请批示。

[附件说明，如有]
附件：1.[附件名称]
      2.[附件名称]

[发文机关署名]
[成文日期]

（联系人：[姓名]，联系电话：[电话号码]）
```

### 七条硬纪律

1. **必须一文一事**——不得把多个请示事项写在一起，需分别行文。
2. **主送机关要单一**——防止多头主送、多头请示，只能有一个主送机关。
3. **不得越级请示**——特殊情况越级请示，须同时抄送被越过的上级机关。
4. **语气要得体**——使用请求性、征询性语言（「妥否，请批示」「当否，请批复」）。
5. **附件要齐全**——必要的政策依据、数据材料、方案应作为附件。
6. **紧急请示要标注时限**——如「以上请示，请于一月内批复」。
7. **注明联系人**——E5 红线：上行文无条件补全。

### 四种常见类型

| 类型 | 事由性质 | 典型事由 |
|---|---|---|
| **政策性请示** | 请求裁决某项政策 | 某项规定与本地实际不符，请求予以变通 |
| **事务性请示** | 请求批准具体事项 | 请求解决资金、请求项目立项 |
| **编制性请示** | 请求批准机构人员编制 | 请求增设机构、增加编制 |
| **请求批准类** | 通用 | 上级授权范围内的具体审批事项 |

> **判定纪律**：类型只影响**理由陈述的重心**，
> 不影响「一文一事 + 单一主送 + 事前行文」这三条硬约束。

## 二、通知

### 标准骨架

```
[发文机关] 关于 [通知事由] 的通知

[主送机关]：

[目的/依据]：
[为何发此通知——目的 + 依据]

[事项]：
一、[事项1]
二、[事项2]
三、[事项3]

[要求]：
[执行要求：时限、责任、纪律]

[发文机关署名]
[成文日期]
```

### 四种常见类型

| 类型 | 特征 |
|---|---|
| **会议通知** | 时间 / 地点 / 参会人 / 议题 / 会前准备 |
| **培训通知** | 对象 / 内容 / 时间地点 / 报名方式 / 考核要求 |
| **批转转发通知** | 原文标题 + 发文字号 + 「现批转/转发给你们」 |
| **任免通知** | 职务变动 + 姓名 + 免去/任命 |

### 三条硬纪律

1. **祈使引导语必须有**——E9 指令态要求：
   「现将有关事项通知如下：」**不得只描述不指令**。
2. **指令态不混陈述态**——不写条件假设句于已实施域。
3. **事项须可执行**——每条事项要有**责任主体 + 时限 + 动作**（D9 例外接口）。

## 三、函

### 发函骨架

```
[发文机关] 关于 [函由] 的函

[受文机关]：

[背景]：
[商洽缘由]

[诉求]：
[具体请求事项]

[结语]：
[专此函达 / 特此函复 / 请予复函]

[发文机关署名]
[成文日期]
```

### 复函骨架

```
[发文机关] 关于 [复函事由] 的复函

[原受文机关]：

[引述来文]：
你单位[来文标题]（[文号]）收悉。

[答复意见]：
[同意 / 原则同意 / 不同意 + 理由 + 限定条件]

[结语]：
此复

[发文机关署名]
[成文日期]
```

### 四种常见类型

| 类型 | 用途 | 结语 |
|---|---|---|
| **商洽函** | 商洽工作、提出请求 | 专此函达，请予复函 |
| **请批函** | 请求批准事项 | 请予批准为盼 |
| **批准函** | 答复批准 | 此复 |
| **询问函** | 询问答复 | 请予函复 |

### 硬纪律

- **平行文不越权**——函是平等机关往来，
  用「请予批准」时不写「务必于×日前完成」这类命令语；
- **复函态度必须明确**——
  「同意 / 原则同意 / 不同意」三者择一，**不得含糊其辞**。

## 四、报告

### 工作报告骨架

```
[发文机关] 关于 [期间] [工作名称] 的报告

[主送机关]：

[概况]：
[做了什么]

[做法与成效]：
[具体措施 + 可核验成效]

[问题]：
[客观化或主观化，见站位铁律]

[下一步]：
[下一阶段安排]

[发文机关署名]
[成文日期]
```

### 情况报告骨架

```
[发文机关] 关于 [事项] 情况的报告

[主送机关]：

[事件/情况陈述]：
[时间、地点、经过、处置]

[初步结论]：
[定性——须走「事实→推演→结论」三步链，见 E10]

[后续安排]：
[处置措施、时限、责任]

[发文机关署名]
[成文日期]
```

### 三条硬纪律（E3）

1. **报告不夹请示**——不得出现「妥否，请批示」「请予批复」。
2. **事后行文**——报告已办事项，请示事前请示。
3. **需要请示的另行走文**。

## 五、纪要

### 标准骨架

```
[发文机关] 会议纪要

[议题]：[会议名称] 第[X]次全体会议

[时间]：[XXXX年X月X日]
[地点]：[会议地点]
[主持]：[主持人姓名、职务]
[出席]：[出席人员单位、姓名]
[请假]：[请假人员单位、姓名]
[列席]：[列席人员单位、姓名]
[记录]：[记录人]

[分歧与协调]：（E13 强制 · 程序性证明功能）
[逐方：主体 → 引用依据(条款) → 核心诉求 → 坚持/让步点]

[议定事项]：
一、[议定内容]（纪实、已决口径）
二、[议定内容]
三、[议定内容]

[例外接口]：（D9 · 有则写）
[责任主体 + 触发条件 + 后续动作/时限/审批路径]

[发文机关署名]
[成文日期]
```

### 三条硬纪律

1. **分歧与协调段不可省**（E13）——
   回避分歧、以「两局未能达成一致」一笔带过即触发红线。
2. **不改写未决意见为已决**。
3. **例外接口有则必写**（E14）——
   实质义务无 D9 配齐即硬退回。

## 六、总结与经验材料

### 总结骨架

```
[发文机关] 关于 [期间] [名称] 工作的总结

[导语]：
[一句话概括范围与成效]

[成效]：
[可核验的数据或事实——数据放在前半篇，见参数卡]

[做法]：
一、[做法1] + [成效收口]
二、[做法2] + [成效收口]
三、[做法3] + [成效收口]

[不足]：
[已解决的问题；本级遗留问题按体裁判断，见反面清单第 10-11 条]

[发文机关署名]
[成文日期]
```

### 经验提炼四步法

| 步 | 做法 |
|---|---|
| 1 | **罗列工作、整理分类**——列出所有工作内容（不分大小），按性质/成效/时间分类 |
| 2 | **归纳亮点、提炼主题**——找创新、有影响力、有成效的工作，提炼关键词与特色表述 |
| 3 | **划分层次、打磨标题**——划分逻辑层次、拟定标题、检查层次间逻辑关系 |
| 4 | **严谨行文、反复修改**——文字精练、标题盖住内容、逻辑层次清楚 |

**层次划分**：遵循 **MECE** 原则（相互独立、完全穷尽），
各层次之间不交叉、不重复。

## 七、填写与导出纪律

```
□ 全部 [方括号] 占位已替换为真实内容？（未替换完 → 禁止导出）
□ 是否误把模板套话当成内容？
  「为切实推进×工作，现将有关情况通报如下」——改成直接说事
□ 请示：一文一事？单一主送？未越级？联系人已填？
□ 通知：祈使引导语在？指令态未混陈述态？
□ 函：平行语气？复函态度明确？
□ 报告：未夹请示？
□ 纪要：分歧与协调段在？例外接口已配齐？
□ 附件：附件说明与附件标题一致？（R13 编号一一映射）
□ 导语：站位取 A/B 而非 C（制度缺陷作切入点）？
□ 数据：未掌握真实数据时用占位，未编造？
```

> **占位符纪律（D-034，最高数据纪律）**
> 只用三种占位写法：
> ```
> 【待补：xx】      缺失的数字/文号/人名/日期，须由用户补齐
> 【示意·待核】     为帮助体感给出的参考量级，使用前必须核实替换
> 【待核对原文】    引用重要论述、上级文件表述拿不准时
> ```
> **导出前必须扫描残留占位符；存在未处理占位符时禁止导出，并列出待补信息。**
